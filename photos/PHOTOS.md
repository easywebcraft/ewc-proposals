# 見本に内蔵するイメージ写真

**相手の写真は使わない**原則はそのまま。ここにあるのは当社が用意した写真で、
見本では必ず「イメージ写真」の札を付けて出す（本物の実績と誤認させないため）。

- 出どころは Unsplash（Unsplash License: 商用可・帰属表示不要・再配布は不可）。
  **写真そのものを配る用途には使わない**（見本ページに内蔵して見せるだけ）
- 取得: `https://images.unsplash.com/photo-<id>?w=<幅>&q=62&fm=jpg&fit=crop`
  ヒーローは w=1200、実績の枠は w=800。1枚 70〜120KB
- ページからは `../photos/<id>.jpg` を相対参照する（data URI で内蔵すると1ページ 500KB になり、
  再生成のたびに git に積まれる）。同じリポジトリ内なので「外部リソースを読み込まない」方針は崩れない。
  ローカルで撮るときは `photos/` ごと kmtest に置くこと
- 検索APIはキーが無いと使えない。`https://unsplash.com/s/photos/<語>` を WebFetch で読んで
  短いID（11文字）を拾い、`https://unsplash.com/photos/<短いID>/download?w=400` の
  リダイレクト先から `photo-<長いID>` を取る。候補を小さく落として1枚に並べ、目で選ぶ
- `sites.json` の `"photos": {"hero": "<長いID>", "gallery": ["<id>", "<id>@50% 85%", ...]}`。
  `@` の後ろは切り出し位置（`background-position`）。縦長の写真を横の枠に入れると
  空ばかりになるので、屋根が下にある写真は `@50% 85%` のように下に寄せる
- **人が写っている写真は使わない**（実在しない従業員に見える）
- **ヒーローだけ写真にするのが基本。** 「空気」を見せる場所なので、よその建物でも違和感が出にくい。
  低コントラストの遠景か、材料の寄りを選ぶ
- **実績（施工事例）の枠には、建物が特定されない材料・道具の寄りだけ。** 「実績」を名乗る場所に
  よその建物を置くと、職人には一目で「うちの仕事ではない」と分かる。写真を入れない枠を残してよい
  （`gallery` に `null`）。「前後」のように作れないものは枠のまま
- 業種の空気が伝わるモチーフを選ぶ（建設: 屋根・現場・木組み／製造: 工場・機械・部品）
